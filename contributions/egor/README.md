# Личный вклад — Егор

## Проект

**«Антискам-тренажёр»** — учебное веб-приложение для отработки безопасного поведения на классифайде через интерактивные сценарии, ветвящиеся диалоги, разбор ошибок и игровые механики.

- [Исходный репозиторий](https://github.com/marlendd/anti-scam-trainer)
- GitHub: [@https-abuser](https://github.com/https-abuser)
- [Pull Requests автора](https://github.com/marlendd/anti-scam-trainer/pulls?q=is%3Apr%20is%3Aclosed%20author%3Ahttps-abuser)
- [Коммиты автора в `main`](https://github.com/marlendd/anti-scam-trainer/commits/main/?author=https-abuser)

## Моя роль

Frontend-разработчик. Отвечал за архитектуру и реализацию клиентской части приложения на React и TypeScript, перенос визуальной концепции в рабочий интерфейс, адаптивность, клиентскую игровую механику и интеграцию frontend с backend API.

В рамках проекта занимался не только отдельными страницами, но и общей структурой frontend-приложения: роутингом, переиспользуемыми UI-компонентами, организацией кода по слоям, состояниями авторизации, отображением тренировочных сценариев, пользовательского прогресса и игровых наград.

## Основной вклад

### 1. Базовая архитектура frontend

Подготовил и развивал frontend-приложение на основе:

- React;
- TypeScript;
- Vite;
- React Router;
- TanStack Query;
- SCSS Modules;
- Feature-Sliced Design;
- ESLint;
- Prettier;

Настроил структуру приложения с разделением на `app`, `pages`, `widgets`, `features`, `entities` и `shared`, чтобы игровые механики, пользовательские сущности и общие компоненты не смешивались между собой.

### 5. Авторизация и интеграция с backend

Реализовывал пользовательские формы и начал перевод авторизации с mock-логики на реальный backend API:

- вход;
- регистрация;
- восстановление пароля;
- отображение текущего пользователя;
- состояние авторизации в интерфейсе;
- logout;
- получение текущего пользователя через TanStack Query.

Для HTTP-запросов используется единый API-клиент. Авторизация backend построена на серверной сессии и `HttpOnly` cookie, поэтому запросы выполняются с `credentials: 'include'`.

Ключевые элементы:

- `useLogin`;
- `useCurrentUser`;
- общий `apiRequest`;
- `currentUserQueryKey`;
- обработка API-ошибок.

Код:

- [`frontend/src/entities/user`](../../frontend/src/entities/user)
- [`frontend/src/shared/api`](../../frontend/src/shared/api)

### 6. Интерактивный тренажёр

Реализовал клиентскую часть основного игрового процесса.

Тренировочный сценарий включает:

- участников диалога;
- товар;
- последовательность сообщений;
- варианты ответа пользователя;
- правильные и рискованные решения;
- автоматическое воспроизведение;
- интерактивный режим прохождения;
- завершение сценария;
- итоговый результат.

Диалог реализован как последовательность элементов `message` и `choice`, что позволяет использовать одну модель как для интерактивного прохождения, так и для демонстрации сценария в глоссарии.

Код:

В глоссарий входят схемы:

Для схем подготовлена единая модель сценариев с демонстрационными диалогами и аналитическим разбором:

### 9. Тренировочные пути покупателя и продавца

Реализовывал страницы прохождения сценариев для разных ролей пользователя.

В интерфейсе предусмотрены:

- список доступных схем;
- статусы прохождения;
- заблокированные и доступные сценарии;
- отображение прогресса;
- область интерактивного чата;
- отдельное поведение роутинга на мобильных устройствах.

На широком экране список сценариев и чат могут отображаться одновременно. На узком экране маршрут определяет, показывается список или текущий диалог.

### 11. Игровая механика пазлов и наград

Проработал и реализовывал механику коллекционных пазлов.

Основная идея:

1. пользователь проходит антискам-сценарий;
2. получает новый фрагмент;
3. фрагмент открывает часть изображения;
4. после сборки полного пазла пользователь получает бонус.

Для frontend был разработан компонент пазла на SVG с единой иллюстрацией и отдельными масками для фрагментов.

Также была спроектирована страница коллекции, на которой каждый пазл имеет:

- собственную иллюстрацию;
- прогресс;
- количество открытых фрагментов;
- связанную награду;
- состояние завершения;
- состояние получения бонуса.

Код:

- [`frontend/src/entities/puzzle`](../../frontend/src/entities/puzzle)
- [`frontend/src/pages`](../../frontend/src/pages)

## Технические решения

В рамках frontend-разработки участвовал в принятии и реализации следующих решений:

- использование React + TypeScript + Vite;
- организация frontend по Feature-Sliced Design;
- использование SCSS Modules вместо глобальных стилей;
- использование TanStack Query для server state;
- отказ от отдельного клиентского `isAuthenticated` как источника истины;
- получение состояния авторизации через текущего пользователя;
- использование серверной `HttpOnly` session-cookie;
- единый API-клиент для запросов к backend;
- route-driven состояние тренировочного интерфейса;
- responsive-first поведение ключевых игровых страниц.
